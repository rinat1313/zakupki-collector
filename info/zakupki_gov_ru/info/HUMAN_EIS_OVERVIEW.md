# ЕИС: кратко для человека

Как пользоваться документацией в этой папке и что нужно для сервиса сбора данных с zakupki.gov.ru (**44-ФЗ и 223-ФЗ**).

---

## Что лежит в папке

| Блок | О чём | Нужен для сбора? |
|---|---|---|
| **`44 фз/`** — альбом ТФФ 16.2 + схемы 16.2.6.9 + WSDL | Как системы обмениваются с ЕИС по **44-ФЗ** (SOAP, выгрузки, getDocs) | **Да** |
| **Требования / схемы 223-ФЗ 16.2** | То же для **223-ФЗ** (HTTPS + XML/REST) | **Да**, если собираете 223 |
| **ГИС НР / ЭМ** | Журнал событий электронных площадок | Нет для обычного сбора извещений/контрактов |

Имена подпапок внутри `44 фз/` на диске могут отображаться «кракозябрами» после распаковки — ориентируйтесь по файлам: `fcsExport.xsd`, `GetDocsWS`, «ЕИС. Альбом ТФФ», «Приложение 1…18».

---

## 44-ФЗ и 223-ФЗ — в чём разница для вас

| | **44-ФЗ** | **223-ФЗ** |
|---|---|---|
| Документы | Извещения, протоколы, **контракты**, планы-графики, РНП… | Извещения, протоколы, **договоры**, планы закупок… |
| Как забирать | **SOAP** (WSDL в папке) + FTP-выгрузки + сервис getDocs | **HTTPS-формы** (REST) + FTP-выгрузки |
| Главный «умный» API | `getDocsMis` / `getDocsRis` / … | `/223/integration/rest/...` |

Оба контура живут на доменах вроде **`int.zakupki.gov.ru`**. Если нужна двухсторонняя проверка сертификата (типично для getDocsMis) — в документации указан отдельный домен **`int44-ttls-cert.zakupki.gov.ru`**.

## Главная задача: сбор данных

Сервис **забирает уже размещённые** XML-сведения и складывает их у вас. Вы задаёте типы документов, регионы/заказчиков и расписание; сервис ходит в ЕИС сам.

Рабочие пути:

| Способ | Когда удобен | Что нужно |
|---|---|---|
| Региональная / rule-выгрузка | Массово наполнить базу | Доступ к выгрузкам |
| **getDocs*** (SOAP, в основном 44, умеет и 223) | По региону, номеру, периоду, НСИ | Код ИС + сертификат + права в ЕИС |
| REST 223 | Точечно по GUID / номеру / ЭТП | Логин интеграции или ЭП |
| Очередь отдачи (РИС) | Поток непубличных документов | Роль РИС + mTLS |

Без регистрации у Оператора ЕИС полноценный API из альбомов недоступен.

---

## Что сделать до разработки

1. Решить: собираем **только 44**, **только 223** или **оба**.
2. Определить роль системы (ФОИВ/ИС, РИС, ВСРЗ, организация…).
3. Получить доступ: код системы, сертификат (часто УЦ Казначейства), права на нужные реестры/заказчиков.
4. Составить список сущностей (например: извещения ЭА/ЭОК, протоколы, контракты, НСИ ОКПД2).
5. Отдать разработчику / AI файл **`AGENT_EIS_INTEGRATION.md`**.

---

## Как пользоваться готовым сервисом

- выбрать закон и типы документов;
- задать регионы или список заказчиков;
- включить расписание;
- смотреть статусы прогонов и искать у себя по реестровому номеру / дате / ИНН.

SOAP и REST руками собирать не нужно — это внутри сервиса.

## Ограничения

- В getDocs — до **1000** организаций в одном запросе.
- Архивы часто отдают **ссылкой**: сначала запрос, потом скачивание (иногда нужно подождать подготовки).
- Для 223 НСИ с FTP с 2025 **не используют** — только сервисы.
- Пароли и сертификаты не класть в чат и git.

## Практичный порядок

1. Получить доступ (лучше сразу под getDocsMis, если цель — широкий сбор 44).  
2. MVP: 2–3 типа документов + один справочник НСИ.  
3. Ежедневная дельта (выгрузка или period-запросы).  
4. Расширить типы по приложениям альбома.  
5. При необходимости — 223 REST и/или сокрытые документы (отдельные права).

Подробная техническая инструкция для AI: **`AGENT_EIS_INTEGRATION.md`**.
